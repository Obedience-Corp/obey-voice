# Changelog

## Unreleased

- A running background job can now be asked for its report from the keyboard: `/work report job-1` prints what the job has done so far ("read 3 files · ran 1 command", or "no tool activity recorded yet") and tells the worker to stop using tools and say what is done, what is not, and where anything it made is. Before, the only way to end a long job was to cancel it, and a cancelled job handed back nothing it found. No model decides whether the report is accepted. On the in-process Ollama worker serving a model on this machine the job keeps its slot and its row and `/workers` show `reporting`; tool calls it had not started are answered "not run: a report was requested", and its next request is a tools-free answer round, with no clock on it, so a slow local model has the time it needs while a cancel still ends the job at once. The answer is delivered cut short with the reason "report requested" (`cut_short_reason` on `job_finished`, a `partial` inbox result, an unfinished reply in the saved conversation). A job asked for a picture may report in words without an image repair; a job whose own answer was already written is delivered as usual; a queued job is left queued; and a CLI, hosted or paid worker, an Ollama worker on another machine or behind a cloud alias, an Obey-managed delegation and a reply moved to the background give the checkpoint only and keep working. An accepted report's checkpoint stays on the task in `/workers` however the job ends, `r` in `/workers` asks the selected task for its report, and a `job_report` event records a report when it is accepted, or when a CLI, hosted, paid or remote worker gives its checkpoint; an Obey-managed delegation and a moved reply give it in the receipt only. A second report while the job runs returns the same checkpoint. If the report round brings no answer the job fails, unless a correction's run was under way with an answer held, which is then delivered cut short as "the corrected run failed". Corrections still waiting when the report is accepted could not apply, and a `/work tell` afterwards is refused with "the job is reporting".
- A running background job can now be corrected from the keyboard: `/work tell job-1 use the other file` reaches job-1 itself. Before, nothing but a cancel could reach a running job, and "use the other file" became chat or a second job queued behind the first. On the in-process Ollama worker serving a model on this machine the job keeps its id, its place and its limits and reads the correction before its next model request or tool call; tool calls it had not started are answered "not run: a correction arrived", and an answer written before the correction is replaced by one that follows it. A queued job gets the correction in its brief. A CLI, hosted or paid worker, an Ollama worker on another machine or behind a cloud alias, an Obey-managed delegation and a reply moved to the background refuse it with the reason, and a correction reaches a job only from the conversation that started it. `/work tell` says at once whether the correction was accepted; the job's row and `/workers` then show `correction included` once a request carrying it was answered, or why it could not apply, and a `job_correction` event records each change. A correction adds no time, requests or spend: when a limit leaves no request for it, or the corrected run fails, the answer the worker already had is delivered cut short. A corrected job asked for a picture is never given an image repair: an answer without the picture is delivered ending "(No image attached.)" instead of failing, and a correction sent while an uncorrected job's repair runs is refused with "the job is finishing". In `/workers`, `e` returns to the conversation with `/work tell` typed for the selected task; if you had started a message, it is kept and the command is shown for you to type instead. When a worker's context fills, its task and corrections are kept as written and only the tool exchanges between them are summarized. Separately, for any Ollama worker job: one with a single model request left no longer spends it summarizing its context and then fails for want of a request to answer with, and one with two left no longer resends a summary after an outage with the last; a background job on the in-process Ollama worker that summarizes with two left now keeps the last for a cut-short answer instead of spending it on a request for more tools and failing; and once a worker had summarized its context, the archived notes it is given were inserted between a tool call and its result, and now come before the newest message, where no call is waiting for its result. The worker conversation shown in `/workers` for a job on the in-process Ollama worker can no longer be replaced by an older one after a failed request.
- With thinking sounds on (`backchannel_enabled`), the short sound played while a slow reply is on its way now uses the current voice after a persona or voice change. Before, the clips were made once at startup, so the previous voice kept saying "Mm-hm." until the next launch. The new voice's clips are made in the background, between replies; until they are ready no thinking sound plays. The record of slow turns that decides whether to play one starts over when the voice or the brain changes, and no thinking sound plays while output is muted.
- In the TUI, a picture in the conversation can be opened in a panel to view it larger, open the original, copy the picture itself or its path, or save a copy. Type `/image`, or click the picture when mouse capture is on. Left and Right move between pictures and Esc closes the panel. A copy is saved to `~/Downloads/<name>` unless you type another path, and never replaces an existing file. Before, a picture could only be opened in the desktop viewer with F3 or `/image N`; there was no way to copy it or save it elsewhere from the chat, and `/image` alone only printed its usage. F3 and `/image N` still open the original directly. Pasting a picture from the clipboard now takes a JPEG as well as a GIF or PNG (on Linux, a GIF and a JPEG as well as a PNG), so a picture copied from the panel pastes into a conversation. On macOS the paste script named a variable with a word AppleScript reserves and did not compile on the system it was checked on, so a clipboard picture was not pasted at all; it now compiles.
- A background job on an Ollama worker whose tools keep returning the same output now says so. Its row in the chat, its line in `/workers` and the job's detail view add `same output for N rounds` once three tool rounds in a row have returned the same output, and a persona on Ollama answering you is told the same about that job, so asked how the job is going it can say so. Rounds compare what the tools returned, not how they were asked, so `ls`, `ls -1` and `ls | cat` printing the same listing count as the same output. Before, a worker that reworded a command each time could repeat itself for 40 rounds with nothing on screen or in the persona's job list saying so, since the repeat guard only catches a call repeated word for word. Nothing is stopped because of it: a job polling something that has not changed yet looks the same. The count clears when the output changes or the job ends and is not saved to the conversation. While a listed job carries the line, the job list comes with one more sentence, the new `system/active-work-same-output.yaml` prompt, saying what it means and that it can be normal while a job waits; otherwise the job list is sent as before. A job list whose entries fill its space now counts every unfinished job it leaves out; before, with long requests and activity it could run past its size limit or leave out a job without counting it.
- A cancelled background job is now reported as stopped only once its worker has returned. A spoken "cancel" waits up to a second and a half for that before it speaks: "Stopped after 40 seconds." as before when the worker has returned, and "Cancelled after 40 seconds; the worker is still stopping." when it has not. Before, it said "Stopped" at once whether or not the worker had stopped. Until the worker returns, the job's line in the chat ends `· stopping…` and `/workers` shows it as `stopping`; afterwards its termination reads `confirmed (worker returned)` instead of `unknown`. The job's slot still goes to the next job at once, and a cancel from `/workers`, `/work cancel` or the desktop app never waits. A spoken "cancel" now ends every job as one act, so a queued job can no longer start on a slot a cancelled one freed, and it also cancels a task an Obey-managed delegation is running, which before it ignored and which did not make "cancel" work on its own. What a cancelled job had done ("read 3 files, ran 41 commands") is saved as a note beside the cancel line in the conversation history (`host_note` on the saved turn), never spoken or shown, so a persona on Ollama or Codex can later say what it got through; before, nothing the job did reached the conversation.
- A persona's reply can now invite several personas at once: `@Milo @Vera, what do you two think?` hands the floor to Milo, then to Vera, in the order mentioned. Before, a reply that @mentioned two personas invited nobody and showed an "Agent handoff skipped" notice asking for one @mention. Each invited persona answers in turn, and no new handoff is looked for until the last of them has answered. An invited persona answers the message that invited it, and on a hosted backend under `hosted_persona_sharing: from_invite` its share starts at that message, so the second persona invited is sent the invitation and the first one's answer. A persona already heard in this message is skipped, as is one that cannot be loaded (with the usual "Agent handoff skipped" notice), and the next one is asked. The limit of three handoffs per message is unchanged. Personas still waiting when the limit is reached, when an invited persona's reply is interrupted or fails, when the persona answering cannot pass the conversation on, or when the personas the reply mentions or the persona selection change before their turn are named in one notice with the reason instead of being dropped silently. Speaking, or stopping the turn, ends the invitation. An `@name` that addresses a persona is now spoken as that persona's display name, so a listener hears who is asked: `@Milo @Vera, what do you two think?` is heard as "Milo, Vera, what do you two think?". Before, the mention was removed from speech. A name the same sentence already says in plain words is said once, and the chat still shows the mention as written. The group-chat prompt (`system/group-chat.yaml`) now tells personas to hand over the floor with `@Name`, that several can be invited in one reply, and that the name is heard in place of the `@Name`; it used to tell them to ask the other agent a direct question by name, which hands over the floor only where a classifier can tell who is addressed. The peer-reply prompt (`system/peer-reply.yaml`) now tells an invited persona to answer the message that addressed it rather than the latest agent's message.
- What a persona on Ollama says before a tool call and what it says after are now separate paragraphs. Before, they were joined with nothing between them (`Let me look.Here it is.`), both on screen while the reply streamed and in the saved reply.
- A background job on an Ollama worker that was made to answer early is now marked cut short, with the reason. That happens when the worker repeats the same tool call with the same result, when a set time limit is nearly used, or when a tiered worker is down to its last model request. The job row says why, such as "done in 41s · cut short: repeated the same tool call", `job_finished` carries `cut_short` and `cut_short_reason`, and the answer is saved to the conversation as an unfinished reply with the reason, so the persona later knows the job did not finish. In the `voice_work_enabled` inbox the result is `partial` with the limitation "cut short: …". Before, whatever the worker wrote in that last round was delivered as an ordinary finished answer.
- A persona on Ollama now knows about its unfinished background jobs. Before, once the exchange that started a job left the six to twelve turns the model is sent, the persona had no record of it: asked "what have you been working on?" twenty minutes into a job, it said nothing was running. Each reply to a person is now given the running and queued jobs with their state, running time, request and recent activity, marked as its own or another persona's. The list is not saved to the conversation. Only the exact status phrases ("status", "what's happening") reported a job before, and they still do. The introduction to the list is the new `system/active-work.yaml` prompt.
- A picture whose Markdown image reference ends a line of prose, such as `Here they are. ![A](</work/a.png>) ![B](</work/b.png>)`, is now attached. Before, only a reference on its own line was recognised, and a trailing one showed as raw Markdown with no picture and no warning. A missing or unusable file at the end of a line reports `[Image unavailable: …]` as an own-line reference does, and the prose before it is still spoken. A reference followed by other text on its line is left as written.
- In the TUI, a tool call that fails while a persona works on its reply no longer puts the screen into its error state. The `✗ tool … failed` line still appears in the chat (with a red ✗) and in Activity, but the presence box keeps showing thinking while the model reads the failure and tries again, and the turn ends idle once the reply lands. Before, one failed command showed `× error` and a red composer until the next tool call, even when the persona retried and succeeded.
- Typing `@` in the chat box lists paths under the campaign root (or the conversation's starting directory outside a campaign). Camp navigation shortcuts work, so `@p/` becomes `@projects/`. Tab accepts, Up/Down/Shift+Tab move, Esc closes the list, and Enter still sends the message as typed. At the start of a message personas and paths share one list. A message that starts with an `@path` such as `@projects/app/` now reaches the current persona instead of being refused as an unknown persona, and the model is told what `@path` is relative to. With `environment_context_enabled: false` the model is not told, so a completed path is inserted in full.
- A persona on a vision-capable Ollama model is now sent the pictures posted in replies, its own and other personas', on the next user message, with a line naming each picture and who posted it. Before, only pictures the user attached reached the model, so a persona could not say what was in a picture it had just posted. They stay for the same three user turns as the user's pictures and count toward the same 32 MiB per request; one that no longer loads is named as no longer attached instead of failing the turn. The chat shows a picture only on the reply that posted it; the saved conversation also records which posted pictures each message carries, so trimming, compaction and a restart keep them.
- A speaking Ollama persona with direct tools can look at a PNG, JPEG or GIF inside its work directory, and nowhere else, with the new `view_image` tool; its next request carries the picture on the message being answered. The picture is saved with that message as one the persona opened, never shown as sent by the user. Workers are not offered the tool. `read_file` on an image now says it is an image file instead of returning its bytes.
- In the TUI, a typed message that names another persona (`@obey …`, `Hey Obey, …`) while an Ollama persona is answering no longer stops that reply. The reply keeps running as that persona's background job and is delivered in its name and voice when it finishes; the named persona answers your message meanwhile. The complete sentences already given stay in the chat marked "continues as job-N" rather than "interrupted", and the job's reply starts with the sentence that was cut off. If the reply ends by handing its work off, the same job does that work with that persona's worker settings. A moved reply is stopped only after three minutes with no activity, as a live reply is, not by `voice_worker_job_budget`; images it links to are attached as for a worker's answer. Its job row names the persona and shows tools that were running at the move. A moved reply that fails partway delivers what arrived and is marked "cut short", and one that does not finish for any reason is saved as unfinished, as a stopped live reply is. Messages that name nobody or the answering persona, spoken input, and personas on other providers still stop the reply.
- An Ollama reply no longer loses a space or paragraph break that the model sends on its own, which showed words run together, such as `Iread` for `I read`.
- In the TUI, typing while a persona works silently no longer silences its reply. Before, a single key pressed at any point before or between the things it said, such as during a long tool call after "Let me look.", kept the rest of the reply from being spoken, with nothing on screen saying why. Typing now stops only speech in progress: a sentence being spoken or already being prepared to speak, and the rest of that reply stays silent as before. The chat box says "Responding — send a message to interrupt" while nothing is being spoken and "Speaking — type to barge in" during speech, and a reply whose speech was stopped says what stopped it, such as "speech stopped by typing", where it said only "interrupted".
- `voice_router_tools: single_call` lets a routed Ollama turn answer chat in the routing request itself: plain text is the reply, and a `route` call hands the turn off. A chat turn is one streamed request instead of two. Personas can choose it with `brain.router`. Model requests in this mode are traced with the new `route_reply` purpose. The default is unchanged.
- Speaking agents can use their permitted tools directly by default. Existing `voice_router_tools: legacy` settings select the same behavior. New configuration writes use `direct`.
- Prompt files that startup copied into the prompts directory and you never edited now follow upgrades. Before, an install kept running the copy it was first given after the shipped prompt changed. Edited files are still never overwritten.
